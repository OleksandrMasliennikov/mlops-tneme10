Input-length experiment: fixed output limit (120 tokens)
| Target input | Actual input tokens | Output tokens | TTFT ms | TPS | Load ms |
|---|---:|---:|---:|---:|---:|
| ~50 | 85 | 120 | 9657.2 | 4.99 | 8.1 |
| ~200 | 275 | 120 | 29629.6 | 3.13 | 9.9 |
| ~500 | 675 | 120 | 78762.3 | 2.51 | 20.7 |

Output-length experiment: fixed input prompt
| Output limit | Input tokens | Actual output tokens | TTFT ms | TPS | Load ms |
|---|---:|---:|---:|---:|---:|
| 50 | 33 | 50 | 4926.7 | 2.58 | 9.0 |
| 200 | 33 | 200 | 273.5 | 2.58 | 9.7 |
| 500 | 33 | 500 | 301.1 | 4.09 | 9.0 |

Коли довжина підказки зросла з 85 до 675 токенів, TTFT збільшився з 9,7 до 78,8 с,
оскільки перед першим токеном модель має обробити весь вхідний текст (prefill).
TPS характеризує наступний етап — декодування відповіді; у моїх вимірюваннях він знизився з 4,99 до 2,51 токена/с.
Це може бути пов’язано зі зростанням витрат на обробку довшого контексту на CPU,
але для впевненого висновку потрібні повторні прогони.
